Ты — Senior Python Developer и архитектор desktop-приложений под Windows.

## ЗАДАЧА

Спроектировать и написать desktop-приложение для Windows 10/11 на Python с GUI.
Программа сканирует папку, находит файлы двух независимых форматов:

  1. `.PGMX` — формат SCM Group (XCam / Maestro), Италия.
     Внутри ZIP-архива лежит XML проекта обработки.
  2. `.SCX` — формат NANXING (Guangdong Nanxing Equipment Co., Ltd), Китай.
     XML-файл программы обработки.

## ГЛАВНОЕ ПРАВИЛО АРХИТЕКТУРЫ

Данные из `.PGMX` и `.SCX` НИКОГДА не пересекаются:
- У каждого формата своя вкладка / своя таблица / свой список файлов.
- Параметры из SCM-файлов не смешиваются с параметрами из NANXING-файлов.
- Сохранение выполняется строго в рамках одного формата.
- Ошибка в одном формате не блокирует работу с другим.

При этом логика работы ОБЩАЯ (единый фреймворк):
- Один и тот же пайплайн: сканирование → распаковка → парсинг → извлечение
  параметров → отображение в таблице → редактирование → валидация → сохранение.
- Разница только в реализации парсера и правил извлечения для каждого формата.
- Архитектура строится по принципу "Стратегия" или "Адаптер":
  общий движок + плагин формата.

## ОГРАНИЧЕНИЯ

- Программа НЕ отправляет данные на станок.
- НЕ генерирует G-code.
- НЕ конвертирует один формат в другой.
- Только чтение, редактирование параметров, сохранение обратно
  в исходный формат с максимальным сохранением структуры.

2. ОБЩИЙ ПАЙПЛАЙН (единый для обоих форматов)
====================================================

Каждый формат проходит через одни и те же этапы:

  ┌─────────────────────────────────────────────────────────┐
  │ 1. SCAN     — найти файлы нужного расширения в папке    │
  │ 2. OPEN     — распаковать (если ZIP) / прочитать XML    │
  │ 3. PARSE    — разобрать структуру, определить параметры │
  │ 4. EXTRACT  — извлечь параметры операций в таблицу      │
  │ 5. DISPLAY  — показать в GUI (таблица + дерево XML)     │
  │ 6. EDIT     — пользователь меняет значения              │
  │ 7. VALIDATE — проверить типы, диапазоны, well-formed    │
  │ 8. DIFF     — показать что изменилось                   │
  │ 9. SAVE     — записать обратно, сохраняя структуру      │
  └─────────────────────────────────────────────────────────┘

Этот пайплайн реализуется в базовом абстрактном классе:

  class BaseFormatHandler(ABC):
      def scan(folder) -> list[FileInfo]
      def open(file) -> DocumentModel
      def extract_params(doc) -> list[OperationRow]
      def apply_changes(doc, changes) -> DocumentModel
      def validate(doc) -> list[ValidationError]
      def save(doc, path) -> None

Конкретные реализации:

  class PgmxFormatHandler(BaseFormatHandler):  # SCM
      ...

  class ScxFormatHandler(BaseFormatHandler):   # NANXING
      ...

4. ОБРАБОТКА .PGMX (SCM Group XCam / Maestro)
====================================================

Файл `.PGMX` — это ZIP-архив.

При открытии:
1. Открыть ZIP через zipfile.
2. Найти внутри главный XML-файл проекта
   (обычно содержит namespace ScmGroup.XCam.MachiningDataModel.ProjectModule
   или имеет расширение .xml).
3. Прочитать XML в память через lxml, сохраняя:
   - XML declaration
   - namespaces (xmlns, xmlns:a, xmlns:b, xmlns:c, xmlns:i, xmlns:d)
   - атрибуты i:type, i:nil
   - порядок элементов
4. Если в архиве есть другие файлы (def.tlgx, .epl, картинки) —
   не трогать их, сохранить при упаковке как есть.

Извлекаемые параметры (в таблицу):

  Для сверления (RoundHole + DrillingOperation):
  - Имя операции (Name из ManufacturingFeature)
  - Диаметр (a:Diameter)
  - Глубина (Depth/EndDepth)
  - Координата X (из Geometries → GeomCartesianPoint → _x,
    связанного через GeometryID)
  - Координата Y (_y)
  - Координата Z (_z)
  - Плоскость (PlaneID → имя плоскости: Top, Bottom, Left, Right, Front, Back)

  Для фрезерования (MillingOperation / RoutingOperation):
  - Имя операции
  - Глубина
  - ID фрезы (в соотвествии def.tlgx)
  - Диаметр инструмента (ToolKey → ссылка на библиотеку)

  Общие параметры заготовки:
  - Длина (WorkPiece/Length или переменная dx1)
  - Ширина (WorkPiece/Width или dy1)
  - Толщина (WorkPiece/Depth или dz1)

Связывание данных:
- ManufacturingFeature → GeometryID → Geometries[Key/ID] → координаты.
- ManufacturingFeature → OperationIDs → Operations[Key/ID] → технология.
- Workplans → MachiningWorkingStep → OperationID + ManufacturingFeatureID.

Редактируемые поля в таблице:
- Диаметр, Глубина, X, Y, Z (числовые).
- Имя операции (текстовое).
- вобор фрезы (в соотвествии def.tlgx)

При сохранении:
- Изменить значения в соответствующих узлах XML.
- Если менялись координаты — обновить и в Geometries, и в Operations
  (в _serializationGeometryDescription внутри ToolpathList).
- Сериализовать через lxml.etree.tostring(xml_declaration=True, encoding=...).
- Заменить XML внутри ZIP-архива, остальные файлы оставить без изменений.
- Сохранить атомарно: временный файл → rename.

5. ОБРАБОТКА .SCX (NANXING)
====================================================

Файл `.SCX` — XML (или, возможно, ZIP с XML внутри — определить
по сигнатуре при первом открытии).

При открытии:
1. Определить кодировку:
   - XML declaration → encoding
   - Если нет: UTF-8 → UTF-8 BOM → GB18030/GBK → Windows-1251
2. Проверить well-formed.
3. Если файл некорректный — показать ошибку, предложить просмотр
   сырого текста, не давать редактировать.

Извлекаемые параметры:
(Точная схема NANXING .SCX неизвестна, поэтому использовать
настраиваемый маппинг из JSON-файла. Пример маппинга ниже.)

  Типичные параметры NANXING:
  - Размеры заготовки: Length, Width, Thickness
  - Операции сверления: X, Y, Diameter, Depth
  - Операции фрезерования: X, Y, Z, FeedRate, SpindleSpeed, ToolDiameter
  - Имя / ID операции

Маппинг хранится в config/nanxing_mapping.json:

{
  "format": "SCX",
  "vendor": "NANXING",
  "namespaces": {},
  "workpiece": {
    "length":  {"xpath": "//Material/@Length",  "type": "float"},
    "width":   {"xpath": "//Material/@Width",   "type": "float"},
    "thickness":{"xpath": "//Material/@Thickness","type": "float"}
  },
  "operations": {
    "container_xpath": "//Operation",
    "fields": [
      {"id": "name",     "xpath": "@Name",       "type": "string", "label": "Имя"},
      {"id": "type",     "xpath": "@Type",       "type": "string", "label": "Тип"},
      {"id": "x",        "xpath": "@X",          "type": "float",  "label": "X"},
      {"id": "y",        "xpath": "@Y",          "type": "float",  "label": "Y"},
      {"id": "z",        "xpath": "@Z",          "type": "float",  "label": "Z"},
      {"id": "diameter", "xpath": "@Diameter",   "type": "float",  "label": "Диаметр"},
      {"id": "depth",    "xpath": "@Depth",      "type": "float",  "label": "Глубина"},
      {"id": "feed",     "xpath": "@FeedRate",   "type": "float",  "label": "Подача"},
      {"id": "spindle",  "xpath": "@SpindleSpeed","type": "int",   "label": "Обороты"}
    ]
  }
}

Пользователь может редактировать этот JSON для адаптации
к конкретной версии формата NANXING.

====================================================
6. ТАБЛИЦА ОПЕРАЦИЙ (общая для обоих форматов)
====================================================

Единый виджет таблицы, но данные в каждой вкладке свои.

Столбцы таблицы:
  | # | Файл | Имя операции | Тип | X | Y | Z | Диаметр | Глубина | Подача | Обороты |

Требования:
- Ячейки X, Y, Z, Диаметр, Глубина, Подача, Обороты — редактируемые.
- Валидация при вводе: только числа, проверка min/max.
- Сортировка по любому столбцу.
- Фильтрация по типу операции (Сверление / Фрезерование / Все).
- Поиск по имени операции.
- Выделение строки → в нижней панели показывается XML-узел.
- Контекстное меню строки:
  - Копировать XPath
  - Показать в дереве XML
  - Сбросить изменения строки

====================================================
7. ДЕРЕВО XML (просмотр одного файла)
====================================================

При выборе файла в списке — в нижней панели отображается
дерево XML (QTreeView + модель на lxml):

- Теги, атрибуты, текстовые значения.
- Разворачивание / сворачивание узлов.
- Контекстное меню:
  - Копировать XPath
  - Копировать значение
  - Копировать внешний вид узла (XML-фрагмент)
- Режим только для чтения (редактирование через таблицу).
- Подсветка изменённых узлов (если значение отличается от исходного).

====================================================
8. СОХРАНЕНИЕ И БЕЗОПАСНОСТЬ
====================================================

- Резервные копии: НЕ создавать (по требованию пользователя).
- Атомарное сохранение: запись во временный файл → rename.
- Перед сохранением показать диалог Diff:
  - Список изменённых файлов.
  - Для каждого файла: таблица "параметр | было | стало".
  - Кнопки: [Сохранить] [Отмена].
- Если изменений нет — не перезаписывать файл.
- Валидация перед сохранением:
  - XML well-formed.
  - Числовые поля в допустимых диапазонах.
  - Обязательные поля не пустые.
- При ошибке сохранения — исходный файл не трогать,
  показать понятное сообщение.
- Для .PGMX: при переупаковке ZIP сохранять ВСЕ файлы архива,
  менять только XML проекта.

12. КРИТЕРИИ ПРИЁМКИ
====================================================

1. Запуск на Windows 10/11 из python main.py.
2. Кнопка "Открыть папку" сканирует папку, находит .PGMX и .SCX.
3. Файлы PGMX появляются на вкладке "SCM", файлы SCX — на вкладке "NANXING".
4. Данные между вкладками НЕ смешиваются.
5. Выбор файла → таблица заполняется операциями.
6. Выбор файла → дерево XML отображает структуру.
7. Редактирование ячейки → значение меняется в модели.
8. Кнопка "Сохранить" на вкладке SCM → диалог Diff → сохранение
   только PGMX-файлов.
9. Кнопка "Сохранить" на вкладке NANXING → диалог Diff → сохранение
   только SCX-файлов.
10. PGMX: ZIP-архив переупаковывается, все файлы кроме XML сохраняются.
11. SCX: XML сохраняется с исходной кодировкой и структурой.
12. Ошибка в одном формате не ломает работу с другим.
13. Сборка через PyInstaller работает.
14. README содержит инструкции.
