# Поддержка формата PGMX (SCM Group)

## Обзор

Реализована полная поддержка формата .PGMX согласно технической спецификации `technical specification.txt`.

## Архитектура

### Стратегия (Strategy Pattern)

```
BaseFormatHandler (абстрактный класс)
├── SCXDocument (существующая реализация для NANXING)
└── PgmxFormatHandler (новая реализация для SCM Group)
```

### Ключевые компоненты

#### 1. `src/core/base_handler.py`
- `BaseFormatHandler` - абстрактный базовый класс с общими методами:
  - `load(path)` - загрузка файла
  - `save(path)` - сохранение файла
  - `get_operations()` - получение списка операций
  - `update_operation(id, changes)` - обновление операции
  - `get_xml_tree()` - получение XML дерева
- `OperationData` - унифицированная структура данных операции
- `FileMetadata` - метаданные файла (материал, толщина, размеры)

#### 2. `src/core/pgmx_handler.py`
Реализация обработчика PGMX:
- **Извлечение ZIP**: PGMX файл распаковывается во временную директорию
- **Поиск XML**: Автоматический поиск основного XML файла (main.xml, program.xml, data.xml)
- **Определение кодировки**: Используется `encoding_detector` для корректного чтения
- **Парсинг операций**: 
  - Поиск по стандартным тегам: Operation, Process, WorkingUnit, ToolPath, MachiningOp
  - Извлечение параметров: feed_rate, speed, depth, tool_id, tool_name
  - Сохранение дополнительных параметров в словаре
- **Сохранение**: Обновление XML и переупаковка ZIP архива

#### 3. `src/ui/main_window.py`
Обновлённое главное окно с вкладками:
- **Вкладка 🇨🇳 NANXING (.SCX)**: Существующий функционал для SCX
- **Вкладка 🇮🇹 SCM (.PGMX)**: Новый функционал для PGMX
- Автоопределение формата по расширению файла
- Раздельное хранение документов для каждого формата

#### 4. `src/models/operations_model.py`
Универсальная модель таблицы операций:
- `SCXOperationData` - данные SCX операции (оригинальная логика)
- `BaseOperationData` - данные PGMX операции (из base_handler)
- Режим PGMX включается через `set_operations()`
- Автоматическое переключение отображения данных

## Пайплайн обработки PGMX

```
1. Пользователь открывает .pgmx файл
   ↓
2. MainWindow._open_file() определяет формат по расширению
   ↓
3. Вызывается _load_pgmx_file()
   ↓
4. Создаётся PgmxFormatHandler
   ↓
5. handler.load() извлекает ZIP → находит XML → парсит
   ↓
6. pgmx_tab.load_data(handler) загружает данные в UI
   ↓
7. Таблица операций показывает данные через OperationsModel
   ↓
8. Дерево XML показывает структуру через SCXTreeView
```

## Отличия форматов

| Характеристика | SCX (NANXING) | PGMX (SCM Group) |
|---------------|---------------|------------------|
| Формат файла | Plain XML | ZIP архив с XML |
| Кодировка | UTF-8, GB18030 | UTF-8 внутри ZIP |
| Структура | Прямой доступ к XML | Извлечение → XML |
| Операции | Тег `<Operation>` | Различные теги (Process, WorkingUnit...) |
| Инструменты | ToolID атрибут | Вложенные элементы или атрибуты |
| Сохранение | Запись XML | Обновление ZIP |

## Зависимости

Существующие зависимости полностью покрывают потребности PGMX:
- `zipfile` (stdlib) - работа с ZIP архивами
- `lxml` - парсинг XML
- `charset-normalizer` - определение кодировки
- `tempfile` (stdlib) - временные файлы
- `shutil` (stdlib) - очистка временных директорий

Новые зависимости не требуются.
